## 1. 两套地址，同一套字段

| 前缀 | 用途 |
|---|---|
| `/mock/api/v1` | 假接口。返回固定示例数据，随时可用。C 联调页面、D 搭测试脚本先用它 |
| `/api/v1` | 真实接口。模块接入一个，对应接口就从 501 变成可用 |

两套接口的路径、参数、返回字段、错误码完全一致。前端只定义一个地址前缀常量，换成 `/api/v1` 即可切到真实接口，不需要改别的代码。

假接口的每个响应都带 `"mock": true`。**假接口的结果只能用于开发联调，不能当作系统的生成结果去演示或提交**（赛题规定：用固定结果冒充现场生成会被取消成绩）。

## 2. 请求与响应

### 请求
- 每个业务请求带 `book_id` 和 `page_no`（从 1 开始）。针对整本书的操作可以不带 `page_no`。
- 与视频有关的请求另带 `play_time`（当前播放到整本视频的第几秒，小数）。
- JSON 请求用 `Content-Type: application/json`；带文件的请求用 `multipart/form-data`，其余参数放表单字段里。

### 响应外壳
所有接口（包括出错时）都返回同一个结构：

```json
{
  "status": "ok",
  "data": { },
  "error": null,
  "run_id": "req-20261111T101500-3f9a1c",
  "elapsed_ms": 12,
  "mock": false
}
```

出错时 `status` 为 `"error"`，`data` 为 `null`，`error` 为：

```json
{"code": "PAGE_NOT_FOUND", "message": "绘本 demo_book 没有第 9 页", "details": {"book_id": "demo_book", "page_no": 9}}
```

- 程序里请按 `error.code` 判断，不要解析 `message` 的中文。
- `run_id` 每次请求唯一。报问题时带上它，可以在服务端日志里定位；生成类任务完成后返回的 `run_id` 可以用 `GET /api/v1/runs/<run_id>` 查到完整的生成记录。
- `elapsed_ms` 是服务端处理耗时，不含网络。

### 3.1 任务

生成类接口立即返回（HTTP 202），前端每隔 1 秒左右查询一次任务：

```json
{
  "task_id": "task-20261111T101500-a1b2c3", "kind": "video", "status": "running",
  "progress": 0.42, "stage": null, "message": "第 2 页：生成视频片段",
  "book_id": "demo_book", "page_no": null, "params": {"force": false},
  "result": null, "error": null, "run_id": null,
  "created_at": "…", "started_at": "…", "finished_at": null
}
```

- `status`：`queued` → `running` → `succeeded` / `failed` / `cancelled`。
- `progress` 是 0 到 1 的小数，`message` 可以直接显示给用户。
- 成功后 `result` 里是结果，`run_id` 可用于追溯；失败后 `error` 里是错误码和原因。
- 同一本书同一页的同类任务没结束时重复提交，返回的是同一个任务（多一个 `"deduplicated": true`），不会重复生成。
- 服务重启时没跑完的任务会变成 `failed`，错误码 `INTERRUPTED`，需要重新提交。

### 3.2 问答返回

```json
{
  "turn_id": "turn-1a2b3c4d", "session_id": "s1", "created_at": "…",
  "book_id": "demo_book", "page_no": 2, "play_time": 12.5,
  "question_text": "月亮掉到哪里去了？", "question_audio_url": null,
  "answer_text": "月亮没有真的掉进水里，朵朵看到的是月亮在小河里的影子。",
  "answer_audio_url": "/mock/api/v1/media/demo_book/audio/page_002.wav",
  "grounded": true,
  "evidence": [
    {"type": "page", "page_no": 2, "quote": "朵朵走到小河边，发现月亮掉进了水里。", "page_image_url": "…"},
    {"type": "video", "page_no": 2, "video_clip_id": "demo_book_p002", "time_range": [11.04, 22.71], "timestamp": 12.54, "video_url": "…"}
  ],
  "snapshot_url": "…",
  "timings": {"asr_ms": 0, "retrieve_ms": 35, "llm_ms": 420, "tts_ms": 210, "first_audio_ms": 665}
}
```

- `evidence` 给出依据。`type: "page"` 用于“跳到这一页”；`type: "video"` 的 `timestamp` 用于“跳到视频这一刻”。
- 书里找不到依据时 `grounded` 为 `false`，`evidence` 为空数组，回答是“书里没有讲到”这类话。前端要有对应的展示。
- `timings.first_audio_ms` 是“说完话到听到第一个字”的首响时间，延迟评测以它为准。假接口里这些是写死的数字，不代表真实性能。
- 真实实现（2026-11-15）：检索用页面原文/旁白/画面/情节/物体的词面匹配，回答由本地 Qwen3 生成；
  `evidence.quote` 会逐字校验，模型编造的依据会被丢弃并降级为 `grounded=false`。
  `answer_audio_url` 在 TTS 未配置或合成失败时为 `null`，不返回占位音频。
- `POST /qa/ask` 未配置大模型时返回 503 `SERVICE_NOT_CONFIGURED`；语音提问识别失败返回 400 `ASR_EMPTY`。
- `session_id` 只允许字母、数字和 `. _ : -`，长度 1–64；不传时服务端生成。

### 3.3 点击识物

请求：

```json
{"book_id": "demo_book", "page_no": 1, "x": 980, "y": 150, "coord_space": "image", "play_time": null}
```

- `x`、`y` 默认是**图片原始尺寸下的像素坐标**（`coord_space: "image"`）。前端要把屏幕上的点击位置按显示缩放比例换算回原图坐标。也可以传 `coord_space: "normalized"`，这时 `x`、`y` 是 0 到 1 的比例。
- 看静态页面时不带 `play_time`，按原页图的物体框查。
- 视频暂停时带上 `play_time`，服务端按最近的关键帧查，坐标是视频画面尺寸下的像素。**不能把原页图的框直接套到视频画面上**，视频里画面是会动的。

返回：

```json
{
  "hit": true,
  "object": {"name": "月亮", "bbox": [898, 68, 1062, 232], "explanation": "月亮是地球的卫星……"},
  "candidates": ["月亮"],
  "source": "page", "page_no": 1, "keyframe_time": null,
  "frame_size": {"width": 1280, "height": 720}, "point": {"x": 980.0, "y": 150.0},
  "audio_url": "…", "timings": {"lookup_ms": 2, "tts_ms": 0}
}
```

- `bbox` 是 `[x1, y1, x2, y2]`，左上角和右下角，单位是 `frame_size` 下的像素。前端画框时按显示比例缩放。
- 多个框重叠时返回面积最小的那个（点到围巾返回“围巾”而不是“朵朵”），`candidates` 列出所有命中的名称。
- 没点到任何物体时 `hit` 为 `false`，`object` 为 `null`。

### 3.4 本地 OCR

`POST /books/<book_id>/ocr`，请求体（都可省略）：

```json
{"page_no": 2, "force": false}
```

- 省略 `page_no` 识别整本。`force: true` 忽略已有结果重新识别；默认已有 `ocr_meta.run_id` 的页面直接复用。
- 立即返回 202 和 `task_id`，用 `GET /tasks/<task_id>` 轮询。任务 `kind` 为 `ocr`。
- 结果为：`{"book_id", "page_count", "succeeded", "failed", "cached", "model", "pages": [...], "errors": [...]}`。
  单页结果包含 `page_no`、`cached`、`run_id`、`full_text`、`block_count`、`char_count`、`elapsed_ms`、`ocr_meta`。
- 写回分页数据的 `ocr_text` 和 `ocr_meta`，并把 `safety_check.status` 重置为 `pending_review`。
- 识别在本机完成，不需要密钥、不产生费用；但页面文字量大或图片大时会占用 CPU，任务进度按页汇报。
- 模型未就绪时返回 503 `OCR_UNAVAILABLE`，`details` 里给出 `missing_dependencies`、`models_ready` 等；先运行 `scripts/download_ocr_models.py`。
- 假接口没有同名 OCR 任务；它的上传任务里用 `ingest` 模拟 OCR。

### 3.5 本地语音识别

`POST /asr`，`multipart/form-data`：

| 字段 | 必填 | 说明 |
|---|---|---|
| `audio` | 是 | 音频文件；支持 wav/mp3/webm/ogg/m4a/mp4。非 wav 会用 imageio-ffmpeg 转成 16 kHz 单声道 |
| `language` | 否 | `auto`（默认）/ `zh` / `en` / `yue` / `ja` / `ko` / `nospeech` |
| `book_id` / `page_no` | 否 | 只用于运行记录，方便按绘本追溯 |

返回（同步，不产生任务）：

```json
{
  "text": "月亮住在哪里呢？朵朵想。",
  "raw_text": "<|zh|><|NEUTRAL|><|Speech|><|withitn|>月亮住在哪里呢？朵朵想。",
  "rich_text": "月亮住在哪里呢？朵朵想。",
  "language": "zh", "emotion": "NEUTRAL", "event": "Speech",
  "duration": 3.88, "elapsed_ms": 2700,
  "audio_bytes": 171304, "audio_format": "wav",
  "run_id": "asr-20261115T005910-aee954",
  "model": "SenseVoiceSmall int8 (ONNX Runtime)",
  "timings": {"asr_ms": 2700}
}
```

- `text` 是去掉 `<|…|>` 标签的纯文本；`raw_text` 保留原始标签；`rich_text` 是官方后处理结果（可能带情感/事件 emoji）。
- 标签依次是语言、情感、声学事件、文本规范化方式。没有说话声时可能返回空 `text` 和 `event: "BGM"` 等，不算错误。
- 识别在本机完成，不需要密钥、不产生费用；首次请求会加载模型（本机约 2–3 秒），之后短音频约 0.2 秒。
- 单次音频默认不超过 60 秒（`PBSC_ASR_MAX_SECONDS`），超过返回 413 `AUDIO_TOO_LONG`。
- 运行时、依赖或模型未就绪时返回 503 `ASR_UNAVAILABLE`；先运行 `scripts/download_asr_models.py`。
- 假接口的 `/mock/api/v1/asr` 返回固定文本，只用于联调。

### 3.6 VLM 内容理解

`POST /books/<book_id>/vlm`，请求体（都可省略）：

```json
{"page_no": 1, "force": false}
```

- 立即返回 202 和 `task_id`，任务 `kind` 为 `vlm`；用 `GET /tasks/<task_id>` 轮询。
- 只要求 VLM 返回：`page_no`、`scene_summary`、`objects[].{name,bbox}`；`contours`、`plot_events`、`confidence` 可选。
- 写回分页数据：`scene_summary`、`objects`、可选 `plot_events`，以及 `vlm_meta`。
- `bbox` 统一为原图像素坐标 `[x1,y1,x2,y2]`。发给模型的图会被缩放，坐标自动换算回原图；`PBSC_VLM_BBOX_FORMAT` 可指定模型的四数字格式是 `xyxy` 还是 `xywh`。
- 页码不一致的任务失败；无效/越界/零面积 bbox 丢弃并写 `warnings`；**没有真实 contours 就只写 bbox，不伪造轮廓**。
- 图片哈希不变时默认复用 `vlm_meta`，`force: true` 才重跑。未配置时返回 503 `VLM_UNAVAILABLE`。
- 上传时设置 `PBSC_VLM_AUTO=1`（或表单 `vlm=1`）会自动提交整本 VLM 任务；上传响应里 `task_ids.vlm` 是它的任务号。

### 3.7 语音合成

`POST /tts`，JSON：

```json
{"text": "床前明月光，疑是地上霜", "voice": "longanyang", "force": false}
```

返回（同步）：

```json
{
  "text": "床前明月光，疑是地上霜",
  "voice": "longanyang",
  "audio_url": "/api/v1/tts-audio/tts_xxxxxxxx.wav",
  "duration": 2.66,
  "is_placeholder": false,
  "model": "cosyvoice-v3-plus",
  "cached": false,
  "timings": {"tts_ms": 6862}
}
```

- 默认走 CosyVoice WebSocket（`PBSC_TTS_PROVIDER=cosyvoice`）；也可切回参考 TTS HTTP（`reference`）。
- 结果按“文字 + 音色 + provider + model”缓存在 `data/tts/`；`force: true` 才重新合成。
- 未配置真实服务时返回占位音频，`is_placeholder=true`，前端会明确标注，不冒充真实配音。
- 音频通过 `GET /tts-audio/<文件名>` 读取；只允许 `data/tts/` 内的文件。
- 单次文本上限 20000 字符；CosyVoice 失败返回 502 `EXTERNAL_SERVICE_ERROR`。
- 页面旁白配音（视频链路）也使用同一个 TTS 客户端；音色由 `COSYVOICE_VOICE` 或请求里的 `voice` 决定。

`POST /generate/audio` 是异步任务：`book_id` + 可选 `page_no`，任务 `kind=audio`。它把每页的 `narration`（没有旁白时用 OCR 原文）交给同一个 TTS 客户端，写回 `narration_audio`，不生成视频。结果包含 `path`、`duration`、`provider`、`is_placeholder`、`voice`、`run_id`。

### 3.8 音色复刻

`POST /voices/cosyvoice`，`multipart/form-data`：

| 字段 | 必填 | 说明 |
|---|---|---|
| `audio` | 是 | 参考音频，WAV/MP3/M4A，5–60 秒，≤10 MB；WAV 会先校验时长 |
| `prefix` | 否 | 音色名称前缀，最多 10 个字母/数字/下划线/短横线，默认 `pbsc` |
| `target_model` | 否 | 绑定模型，默认 `COSYVOICE_MODEL`（如 `cosyvoice-v3-plus`） |
| `language_hints` | 否 | 逗号分隔，默认 `zh` |

返回 202：`{"voice_id": "...", "status": "DEPLOYING", "target_model": "...", "voice": {...}}`。音色审核完成后 `status` 变成 `OK`；未通过为 `UNDEPLOYED`。

- 查询列表：`GET /voices/cosyvoice?prefix=&page_index=0&page_size=20`。
- 查询详情：`GET /voices/cosyvoice/<voice_id>`。
- 替换参考音频：`PUT /voices/cosyvoice/<voice_id>`，同样用 `audio` 字段。
- 删除：`DELETE /voices/cosyvoice/<voice_id>`。
- 选定：`POST /voices/cosyvoice/selection`，JSON `{"voice_id": "..."}`；保存到 `data/voice_selection.json`。之后 `/tts` 和 `/generate/audio` 没显式传 `voice` 时默认用它。
- 复刻音色绑定 `target_model`，不能跨模型使用；合成时模型要与创建时一致。
- 密钥只放 `.env`；接口只返回 `voice_id`/状态，不回显 Key。

## 4. 分页数据格式（临时草案 0.1，待 B 定稿）

每本书一个 `book.json`。书级字段：`schema_version`、`book_id`、`title`、`language`、`age_range`、`source_reference`、`characters`（人物设定表）、`pages`、`video`。

`characters` 的每一项：`character_id`、`name`（规范称呼，旁白和提示词都以它为准）、`aliases`（原文里的其他叫法）、`appearance`（外观，用于视频提示词）、`personality`。

每页的字段，前 14 个是共同约定里列出的：

| 字段 | 类型 | 说明 | 谁写入 |
|---|---|---|---|
| `book_id` `page_no` | 字符串 / 整数 | 页码从 1 开始 | 上传时 |
| `page_image` | 字符串 | 相对绘本目录的路径，如 `pages/page_001.png` | 上传时 |
| `ocr_text` | `{"full_text": "…", "blocks": [{"text": "…", "bbox": [x1,y1,x2,y2], "score": 0.99}]}`。`full_text` 按行用 `\n` 连接；`blocks` 按阅读顺序排列，`bbox` 为轴对齐像素框，`score` 可选 | 原文及文字框 | B（RapidOCR 节点） |
| `narration` | 字符串 | 朗读旁白 | A（旁白节点） |
| `characters` | `[{"character_id", "name", "appearance"}]` | 本页出现的人物 | B |
| `objects` | `[{"object_id", "name", "bbox", "explanation", "confidence"?, "contours"?}]` | 物体、坐标框、简短讲解；`contours` 为可选的真实贴边轮廓 | B（VLM 节点） |
| `scene_summary` | 字符串 | 画面摘要 | B（VLM 节点） |
| `plot_events` | 字符串数组 | 本页情节 | B（VLM 节点） |
| `video_clip_id` | 字符串 | 如 `demo_book_p001` | A（视频节点） |
| `time_range` | `[开始秒, 结束秒]` | 本页在整本视频里的时间段，相邻页首尾相接 | A（视频节点） |
| `keyframes` | `[{"time", "page_no", "description", "frame_size", "objects": [{"name", "bbox", "explanation"}]}]` | 关键帧时间、画面描述、物体框 | B |
| `source_reference` | 对象 | 来源信息 | 上传时 / E |
| `safety_check` | `{"status", "age_range", "reviewer", "notes"}` | `status` 取 `pending_review` / `approved` / `rejected` | B 的安全节点 + 人工复核 |

另外的字段：

| 字段 | 说明 | 谁写入 |
|---|---|---|
| `image_size` | `{"width", "height"}`，所有 `bbox` 以它为基准 | 上传时 |
| `ocr_meta` | OCR 追溯信息：`run_id`、`engine`、`model`、`text_score`、`use_cls`、`block_count`、`char_count`、`elapsed_ms`、`generated_at`；没有识别过时为 `null` | B（RapidOCR 节点） |
| `vlm_meta` | VLM 追溯信息：`run_id`、`provider`、`protocol`、`model`、`image_sha256`、`sent_size`、`object_count`、`warnings`、`generated_at`、`elapsed_ms`；没有分析过时为 `null` | B（VLM 节点） |
| `narration_meta` | 旁白是怎么来的：`run_id`、`method`（`llm` / `passthrough_ocr` / `fallback_passthrough`）、提示词版本、模型、检查结果、是否需要人工复核 | A |
| `narration_audio` | 配音文件路径、时长、是否占位音频 | A |
| `video_prompt` | 本页图生视频用的提示词 | A |
| `video_meta` | 成片路径与时长、原始片段、服务与模型、是否降级片段及原因、字幕时间表、`clip_sha256` | A |

给 B 的三点说明：

1. **旁白重新生成时，A 会把 `safety_check.status` 重置为 `pending_review`**，之前的复核结论作废。
2. **A 不会改动 `keyframes`**。片段重新生成后 `video_meta.clip_sha256` 会变，B 的索引可以据此判断关键帧是否过期。
3. 片段索引另有一份独立文件 `video/clip_index.json`，内容与 `book.video` 相同：每个片段的 `video_clip_id`、`page_no`、`time_range`、`narration`、`prompt`、`clip_path`。

## 5. 假接口的调试办法

示例绘本是仓库自带的 `demo_book`（《朵朵找月亮》，3 页，队伍自制，可以放心演示），假接口只认这一个 `book_id`。

**调出各种界面状态。** 下面两个参数放在地址后面或 JSON 里都可以：

| 参数 | 效果 |
|---|---|
| `mock_delay_ms=1500` | 这次请求延迟 1.5 秒再返回（最多 10 秒），用来调“等待中” |
| `mock_fail=1` | 这次请求返回 500 `MOCK_FAILURE`；用在 `/generate/*` 上则是任务跑到一半失败，用来调“失败” |

- “无结果”：问一个书里没有的问题（比如“恐龙吃什么”），或点击画面空白处（比如 `x=5, y=5`）。
- “长任务进度”：`POST /generate/video` 后轮询任务，约 8 秒内依次经过配音、生成片段、合成三个阶段。

**示例问题**（问题里包含关键词即可命中）：围巾什么颜色、谁告诉朵朵的、月亮掉到哪里去了、最后怎么样了、朵朵看见了什么、朵朵在想什么。

**用 curl 试一下**（先 `python -m server` 启动服务）：

```bash
curl http://127.0.0.1:8000/mock/api/v1/books/demo_book/pages/1
```

```bash
curl -X POST http://127.0.0.1:8000/mock/api/v1/qa/ask -H "Content-Type: application/json" -d "{\"book_id\":\"demo_book\",\"page_no\":2,\"question\":\"月亮掉到哪里去了\"}"
```

```bash
curl -X POST http://127.0.0.1:8000/mock/api/v1/touch/identify -H "Content-Type: application/json" -d "{\"book_id\":\"demo_book\",\"page_no\":1,\"x\":980,\"y\":150}"
```

假接口的限制：对话历史只存在内存里，重启就没了；上传的文件会被真实校验但不保存；语音识别永远返回同一句话；音频是占位提示音，不是真人声。

## 前后端联调增补

- 根路径 `/` 托管 `前端/`；真实和假接口前缀保持不变，`?mock=1` 仅控制页面选择哪套接口。
- `/api/v1/touch/identify` 已实现结构化标注查表。视频缺少关键帧时返回 `hit=false` 和原因，不沿用原图坐标。物体框自动生成及 VLM 兜底尚待实现。
- 音色接口沿用前端原协议，不使用本文件的业务响应外壳：`GET /api/voice/status`、`GET/POST /api/voices`、`POST /api/voices/selection`、`POST /api/voices/{id}/speech`。最后一个返回音频二进制；未配置服务时状态为不可用、列表为空、写请求返回503。配置 `PBSC_VOICE_SERVICE_URL` 后转发至独立服务。
- ASR、TTS、QA 和历史均已有真实实现（2026-11-15）：ASR 走本地 SenseVoice，TTS 走 CosyVoice，
  QA 走“检索 + 本地 Qwen3 + 依据校验”，历史按 session 落盘到 `data/history/`。
  生成节点中的旁白 TTS 仍是独立链路。需要启动 `scripts/start_llm.ps1` 才有问答能力。

## 正式模式整本 PDF 导入

- POST /api/v1/pdf-imports 接收 multipart 的 pdf 字段和可选 title，返回 202 及导入记录。正式页面用 GET /api/v1/pdf-imports/{id} 查询 running、cancelling、paused、completed、trash。GET /api/v1/pdf-imports 列出进行中和暂停的导入。
- paused 返回原书页码 page 和 reason。POST /api/v1/pdf-imports/{id}/decision 接收 action=skip|retry|cancel。skip 和 retry 需回传暂停时的 page。retry 可通过 multipart 的 replacement 上传一张替换图片。
- completed 返回 book_id，沿用现有绘本接口。跳过页保留原页码和空白占位，并设置 import_skipped=true。正常页的 source_reference.text_source 为 pdf_text_layer 或 ocr。
- GET /api/v1/pdf-trash 列出 7 天内的失败和取消记录，可通过 GET /api/v1/pdf-trash/{id}/original 下载保留的原文件，通过 DELETE /api/v1/pdf-trash/{id} 立即删除。到期记录在启动或访问导入/垃圾桶时清理。该垃圾桶与书架一样用于单用户本机演示。
- PBSC_PDF_MAX_MB、PBSC_PDF_MAX_PAGES、PBSC_PDF_MAX_EDGE、PBSC_PDF_MAX_PIXELS 的默认值分别为 100 MiB、150 页、3000 像素、900 万像素。超大页按比例缩小。PDF 成功入库后清理原件，失败时保留完整且未超文件大小上限的原件。
