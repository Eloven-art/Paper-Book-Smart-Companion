状态：**草案**。第 1～3、5 节是 A 起草的接口约定，请全员确认；第 4 节的分页数据格式本应由 B 起草，这里是 A 为了让假接口先跑起来暂拟的，B 冻结 v1.0 后以 B 的为准。

## 1. 两套地址，同一套字段

| 前缀 | 用途 |
|---|---|
| `/mock/api/v1` | 假接口。返回固定示例数据，随时可用。C 联调页面、D 搭测试脚本先用它 |
| `/api/v1` | 真实接口。模块接入一个，对应接口就从 501 变成可用 |

两套接口的路径、参数、返回字段、错误码完全一致。前端只定义一个地址前缀常量，换成 `/api/v1` 即可切到真实接口，不需要改别的代码。

假接口的每个响应都带 `"mock": true`。**假接口的结果只能用于开发联调，不能当作系统的生成结果去演示或提交**（赛题规定：用固定结果冒充现场生成会被取消成绩）。

## 2. 请求与响应

### 请求
- 每个业务请求带 `book_id` 和 `page_no`（从 1 开始）。针对整本书的操作可以不带 `page_no`。
- 与视频有关的请求另带 `play_time`（当前播放到整本视频的第几秒，小数）。
- JSON 请求用 `Content-Type: application/json`；带文件的请求用 `multipart/form-data`，其余参数放表单字段里。

### 响应外壳
所有接口（包括出错时）都返回同一个结构：

```json
{
  "status": "ok",
  "data": { },
  "error": null,
  "run_id": "req-20261111T101500-3f9a1c",
  "elapsed_ms": 12,
  "mock": false
}
```

出错时 `status` 为 `"error"`，`data` 为 `null`，`error` 为：

```json
{"code": "PAGE_NOT_FOUND", "message": "绘本 demo_book 没有第 9 页", "details": {"book_id": "demo_book", "page_no": 9}}
```

- 程序里请按 `error.code` 判断，不要解析 `message` 的中文。
- `run_id` 每次请求唯一。报问题时带上它，可以在服务端日志里定位；生成类任务完成后返回的 `run_id` 可以用 `GET /api/v1/runs/<run_id>` 查到完整的生成记录。
- `elapsed_ms` 是服务端处理耗时，不含网络。

### 错误码

| HTTP | code | 含义 |
|---|---|---|
| 400 | `INVALID_ARGUMENT` | 参数缺失或格式不对，`details.field` 指出是哪个 |
| 400 | `POINT_OUT_OF_RANGE` | 点击坐标超出画面 |
| 400 / 413 / 415 | `UPLOAD_MISSING` `UPLOAD_EMPTY` `UPLOAD_TOO_LARGE` `UPLOAD_TYPE_NOT_ALLOWED` `UPLOAD_CONTENT_MISMATCH` `UPLOAD_IMAGE_CORRUPT` `UPLOAD_IMAGE_TOO_SMALL` `UPLOAD_IMAGE_TOO_LARGE` `UPLOAD_TOO_MANY` | 上传文件没通过校验 |
| 404 | `BOOK_NOT_FOUND` `PAGE_NOT_FOUND` `TASK_NOT_FOUND` `FILE_NOT_FOUND` `RUN_NOT_FOUND` `NOT_FOUND` | 资源不存在 |
| 404 | `PAGE_IMAGE_MISSING` | 分页数据里登记的页面图片在磁盘上找不到 |
| 405 | `METHOD_NOT_ALLOWED` | 请求方法不对 |
| 409 | `BOOK_EXISTS` | 绘本 ID 已被占用 |
| 429 | `BUDGET_EXCEEDED` | 达到预算上限 |
| 500 | `INTERNAL_ERROR` | 服务内部错误，凭 `run_id` 找 A |
| 501 | `NOT_IMPLEMENTED` | 真实模块还没接入，`details.mock_path` 给出可用的假接口 |
| 502 | `EXTERNAL_SERVICE_ERROR` | 外部服务调用失败 |
| 503 | `SERVICE_NOT_CONFIGURED` | 外部服务没配置 |

## 3. 接口列表

“真实”一列：✅ 已可用；⏳ 返回 501，先用假接口。

| 方法与路径 | 作用 | 真实 |
|---|---|---|
| `GET /health` | 服务状态；真实接口里还会列出哪些外部服务没配置 | ✅ |
| `GET /books` | 书架列表 | ✅ |
| `POST /books` | 上传绘本页面图片（表单字段 `pages` 可重复，按上传顺序编页码；可选 `title`、`book_id`） | ✅ |
| `GET /books/<book_id>` | 书级信息、人物设定表、整本视频与片段索引 | ✅ |
| `GET /books/<book_id>/pages` | 全部分页数据 | ✅ |
| `GET /books/<book_id>/pages/<page_no>` | 一页的分页数据 | ✅ |
| `GET /media/<book_id>/<相对路径>` | 页面图片、音频、视频文件；支持分段请求，视频可拖动 | ✅ |
| `POST /generate/narration` | 提交旁白生成任务，返回 `task_id` | ✅ |
| `POST /generate/video` | 提交视频生成任务。带 `page_no` 只生成该页；不带则生成整本。`force: true` 忽略缓存 | ✅ |
| `GET /tasks/<task_id>` | 任务状态与进度 | ✅ |
| `GET /tasks?book_id=` | 任务列表 | ✅（假接口没有） |
| `POST /tasks/<task_id>/cancel` | 取消任务 | ✅（假接口没有） |
| `GET /runs/<run_id>` | 一次生成的完整记录 | ✅（假接口没有） |
| `GET /costs` | 费用台账汇总 | ✅（假接口没有） |
| `POST /asr` | 语音识别（表单字段 `audio`） | ⏳ |
| `POST /tts` | 语音合成（`text`） | ⏳ |
| `POST /qa/ask` | 提问。文字用 `question`，语音用表单字段 `audio`；带 `book_id`、`page_no`，看视频时带 `play_time`，可带 `session_id` | ⏳ |
| `POST /touch/identify` | 点击识物（见 3.3） | ⏳ |
| `GET /history?session_id=` | 多模态对话历史 | ⏳ |

### 3.1 任务

生成类接口立即返回（HTTP 202），前端每隔 1 秒左右查询一次任务：

```json
{
  "task_id": "task-20261111T101500-a1b2c3", "kind": "video", "status": "running",
  "progress": 0.42, "stage": null, "message": "第 2 页：生成视频片段",
  "book_id": "demo_book", "page_no": null, "params": {"force": false},
  "result": null, "error": null, "run_id": null,
  "created_at": "…", "started_at": "…", "finished_at": null
}
```

- `status`：`queued` → `running` → `succeeded` / `failed` / `cancelled`。
- `progress` 是 0 到 1 的小数，`message` 可以直接显示给用户。
- 成功后 `result` 里是结果，`run_id` 可用于追溯；失败后 `error` 里是错误码和原因。
- 同一本书同一页的同类任务没结束时重复提交，返回的是同一个任务（多一个 `"deduplicated": true`），不会重复生成。
- 服务重启时没跑完的任务会变成 `failed`，错误码 `INTERRUPTED`，需要重新提交。

### 3.2 问答返回

```json
{
  "turn_id": "turn-1a2b3c4d", "session_id": "s1", "created_at": "…",
  "book_id": "demo_book", "page_no": 2, "play_time": 12.5,
  "question_text": "月亮掉到哪里去了？", "question_audio_url": null,
  "answer_text": "月亮没有真的掉进水里，朵朵看到的是月亮在小河里的影子。",
  "answer_audio_url": "/mock/api/v1/media/demo_book/audio/page_002.wav",
  "grounded": true,
  "evidence": [
    {"type": "page", "page_no": 2, "quote": "朵朵走到小河边，发现月亮掉进了水里。", "page_image_url": "…"},
    {"type": "video", "page_no": 2, "video_clip_id": "demo_book_p002", "time_range": [11.04, 22.71], "timestamp": 12.54, "video_url": "…"}
  ],
  "snapshot_url": "…",
  "timings": {"asr_ms": 0, "retrieve_ms": 35, "llm_ms": 420, "tts_ms": 210, "first_audio_ms": 665}
}
```

- `evidence` 给出依据。`type: "page"` 用于“跳到这一页”；`type: "video"` 的 `timestamp` 用于“跳到视频这一刻”。
- 书里找不到依据时 `grounded` 为 `false`，`evidence` 为空数组，回答是“书里没有提到”这类话。前端要有对应的展示。
- `timings.first_audio_ms` 是“说完话到听到第一个字”的首响时间，延迟评测以它为准。假接口里这些是写死的数字，不代表真实性能。

### 3.3 点击识物

请求：

```json
{"book_id": "demo_book", "page_no": 1, "x": 980, "y": 150, "coord_space": "image", "play_time": null}
```

- `x`、`y` 默认是**图片原始尺寸下的像素坐标**（`coord_space: "image"`）。前端要把屏幕上的点击位置按显示缩放比例换算回原图坐标。也可以传 `coord_space: "normalized"`，这时 `x`、`y` 是 0 到 1 的比例。
- 看静态页面时不带 `play_time`，按原页图的物体框查。
- 视频暂停时带上 `play_time`，服务端按最近的关键帧查，坐标是视频画面尺寸下的像素。**不能把原页图的框直接套到视频画面上**，视频里画面是会动的。

返回：

```json
{
  "hit": true,
  "object": {"name": "月亮", "bbox": [898, 68, 1062, 232], "explanation": "月亮是地球的卫星……"},
  "candidates": ["月亮"],
  "source": "page", "page_no": 1, "keyframe_time": null,
  "frame_size": {"width": 1280, "height": 720}, "point": {"x": 980.0, "y": 150.0},
  "audio_url": "…", "timings": {"lookup_ms": 2, "tts_ms": 0}
}
```

- `bbox` 是 `[x1, y1, x2, y2]`，左上角和右下角，单位是 `frame_size` 下的像素。前端画框时按显示比例缩放。
- 多个框重叠时返回面积最小的那个（点到围巾返回“围巾”而不是“朵朵”），`candidates` 列出所有命中的名称。
- 没点到任何物体时 `hit` 为 `false`，`object` 为 `null`。

## 4. 分页数据格式（临时草案 0.1，待 B 定稿）

每本书一个 `book.json`。书级字段：`schema_version`、`book_id`、`title`、`language`、`age_range`、`source_reference`、`characters`（人物设定表）、`pages`、`video`。

`characters` 的每一项：`character_id`、`name`（规范称呼，旁白和提示词都以它为准）、`aliases`（原文里的其他叫法）、`appearance`（外观，用于视频提示词）、`personality`。

每页的字段，前 14 个是共同约定里列出的：

| 字段 | 类型 | 说明 | 谁写入 |
|---|---|---|---|
| `book_id` `page_no` | 字符串 / 整数 | 页码从 1 开始 | 上传时 |
| `page_image` | 字符串 | 相对绘本目录的路径，如 `pages/page_001.png` | 上传时 |
| `ocr_text` | `{"full_text": "…", "blocks": [{"text": "…", "bbox": [x1,y1,x2,y2]}]}` | 原文及文字框 | B |
| `narration` | 字符串 | 朗读旁白 | A（旁白节点） |
| `characters` | `[{"character_id", "name", "appearance"}]` | 本页出现的人物 | B |
| `objects` | `[{"object_id", "name", "bbox", "explanation"}]` | 物体、坐标框、简短讲解 | B |
| `scene_summary` | 字符串 | 画面摘要 | B |
| `plot_events` | 字符串数组 | 本页情节 | B |
| `video_clip_id` | 字符串 | 如 `demo_book_p001` | A（视频节点） |
| `time_range` | `[开始秒, 结束秒]` | 本页在整本视频里的时间段，相邻页首尾相接 | A（视频节点） |
| `keyframes` | `[{"time", "page_no", "description", "frame_size", "objects": [{"name", "bbox", "explanation"}]}]` | 关键帧时间、画面描述、物体框 | B |
| `source_reference` | 对象 | 来源信息 | 上传时 / E |
| `safety_check` | `{"status", "age_range", "reviewer", "notes"}` | `status` 取 `pending_review` / `approved` / `rejected` | B 的安全节点 + 人工复核 |

另外的字段：

| 字段 | 说明 | 谁写入 |
|---|---|---|
| `image_size` | `{"width", "height"}`，所有 `bbox` 以它为基准 | 上传时 |
| `narration_meta` | 旁白是怎么来的：`run_id`、`method`（`llm` / `passthrough_ocr` / `fallback_passthrough`）、提示词版本、模型、检查结果、是否需要人工复核 | A |
| `narration_audio` | 配音文件路径、时长、是否占位音频 | A |
| `video_prompt` | 本页图生视频用的提示词 | A |
| `video_meta` | 成片路径与时长、原始片段、服务与模型、是否降级片段及原因、字幕时间表、`clip_sha256` | A |

给 B 的三点说明：

1. **旁白重新生成时，A 会把 `safety_check.status` 重置为 `pending_review`**，之前的复核结论作废。
2. **A 不会改动 `keyframes`**。片段重新生成后 `video_meta.clip_sha256` 会变，B 的索引可以据此判断关键帧是否过期。
3. 片段索引另有一份独立文件 `video/clip_index.json`，内容与 `book.video` 相同：每个片段的 `video_clip_id`、`page_no`、`time_range`、`narration`、`prompt`、`clip_path`。

## 5. 假接口的调试办法

示例绘本是仓库自带的 `demo_book`（《朵朵找月亮》，3 页，队伍自制，可以放心演示），假接口只认这一个 `book_id`。

**调出各种界面状态。** 下面两个参数放在地址后面或 JSON 里都可以：

| 参数 | 效果 |
|---|---|
| `mock_delay_ms=1500` | 这次请求延迟 1.5 秒再返回（最多 10 秒），用来调“等待中” |
| `mock_fail=1` | 这次请求返回 500 `MOCK_FAILURE`；用在 `/generate/*` 上则是任务跑到一半失败，用来调“失败” |

- “无结果”：问一个书里没有的问题（比如“恐龙吃什么”），或点击画面空白处（比如 `x=5, y=5`）。
- “长任务进度”：`POST /generate/video` 后轮询任务，约 8 秒内依次经过配音、生成片段、合成三个阶段。

**示例问题**（问题里包含关键词即可命中）：围巾什么颜色、谁告诉朵朵的、月亮掉到哪里去了、最后怎么样了、朵朵看见了什么、朵朵在想什么。

**用 curl 试一下**（先 `python -m server` 启动服务）：

```bash
curl http://127.0.0.1:8000/mock/api/v1/books/demo_book/pages/1
```

```bash
curl -X POST http://127.0.0.1:8000/mock/api/v1/qa/ask -H "Content-Type: application/json" -d "{\"book_id\":\"demo_book\",\"page_no\":2,\"question\":\"月亮掉到哪里去了\"}"
```

```bash
curl -X POST http://127.0.0.1:8000/mock/api/v1/touch/identify -H "Content-Type: application/json" -d "{\"book_id\":\"demo_book\",\"page_no\":1,\"x\":980,\"y\":150}"
```

假接口的限制：对话历史只存在内存里，重启就没了；上传的文件会被真实校验但不保存；语音识别永远返回同一句话；音频是占位提示音，不是真人声。
