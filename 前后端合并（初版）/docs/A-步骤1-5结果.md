## 步骤 1：摸清现有后端

交付：
- [A1-参考后端接口清单.md](A1-参考后端接口清单.md)：结论、启动方式、实测发现的问题、外部服务与计费口径。
- [A1-参考后端实测结果.md](A1-参考后端实测结果.md)：35 行的逐接口表格（方法、路径、用途、依赖、结论、HTTP 状态、耗时、费用、返回摘要）。
- `scripts/smoke_reference_server.py`：生成上表的脚本，配置好服务后可重跑。
- `scripts/run_reference_server.py`：不改参考代码的启动脚本。

结果：已跑通 17，依赖外部 API 待验证 17，不可用 1。

主要发现（都经过实际运行确认）：
1. 前端页面请求的地址带 `/tts-story-book` 前缀，后端没有注册，本机直接运行时页面上的功能全部 404。
2. 中文 Windows 上把输出重定向时，服务在启动阶段就因表情符号编码失败而崩溃。
3. 视频生成没有任务状态和失败通知，并且依赖阿里云 OSS 图床。
4. 文件接口可以读到服务目录以外的文件，且服务对整个局域网开放。
5. 另有 8 处缺陷，其中语音识别把同一段音频识别两遍会直接拖慢交互延迟。

未完成：17 个外部接口的真实调用、费用和耗时。

## 步骤 4：故事旁白

交付：`agents/story_agent.py`、`agents/llm_client.py`、`configs/prompts/narration_v1.txt`。做法见 [后端使用说明.md](后端使用说明.md) 第 4 节。

对应分工说明的要求：
- “改写与讲述原书，不是另编新故事”：提示词明确限定只讲本页已有内容；生成后用依据度和原文保留度做程序化检查，不通过就重试，最后退回原文直读。
- “保持人物称呼和情节一致”：提示词带人物设定表并要求称呼一致；检查原文里的人物是否都被讲到、规范称呼是否被换掉；上一页旁白作为承接上下文。
- “复用参考代码的故事模块并改提示词”：调用方式与 `../赛题内容/参考代码/text.py` 相同（OpenAI 兼容接口，同一组环境变量），提示词换成讲述原书的版本。没有改成某一家厂商专用的写法。

已验证（本机模拟的大模型服务）：正常输出被采纳并写回；编造的故事被拒绝并带原因重试；连续三次编造则退回原文；503 自动重试后成功；连续 500 则退回原文并记录原因；大模型未配置时原文直读；旁白变化后安全复核状态重置。

未验证：真实大模型的输出质量、耗时、token 费用。检查用的阈值（依据度 0.15 / 0.30 等）是按示例绘本估的，需要在真实模型和官方绘本上校准。
