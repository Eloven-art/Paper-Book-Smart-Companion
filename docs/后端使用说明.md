# 后端使用说明

适用于 `server/`（服务）、`agents/`（生成节点）、`configs/`、`scripts/`。接口字段见 [接口约定_v0.1.md](接口约定_v0.1.md)。

## 1. 安装与启动

需要 Python 3.10 及以上（已在 3.13 上验证）。不需要另装 ffmpeg，MoviePy 自带。

```bash
python -m venv .venv
```

```bash
.venv\Scripts\pip install -r requirements.txt
```

```bash
.venv\Scripts\python -m server
```

Linux / macOS 把 `.venv\Scripts\` 换成 `.venv/bin/`。启动后：

- 真实接口 `http://127.0.0.1:8000/api/v1/health`
- 假接口 `http://127.0.0.1:8000/mock/api/v1/health`
- 如果仓库里有 `web/index.html`，根地址会托管前端页面

默认只监听本机。平板联调时用 `python -m server --host 0.0.0.0`，平板访问电脑的局域网地址。

单进程运行即可。任务队列在进程内，不要用多进程方式部署，否则各进程看不到彼此的任务。

## 2. 配置

把 `.env.example` 复制成 `.env` 再填写。`.env` 已被 git 忽略，密钥只放这里。

| 外部服务 | 变量 | 没配置时的降级方案 |
|---|---|---|
| 大模型 | `SIMPLE_STORY_WRITER_URL` / `_API_KEY` / `_MODEL` | 旁白直接用原文 |
| 语音合成 | `TTS_API_URL` | 占位提示音（时长按字数估算，每句开头一声轻响） |
| 图生视频 | `IMAGE2VIDEO_URL` / `_API_KEY` / `_MODEL` | 静态页图缓慢推近 |

降级方案的作用是让整条链路在没有外部服务时也能跑通、能联调，**它们不是生成成果**。所有降级结果都会在分页数据、任务结果和运行记录里标明（`method`、`is_placeholder`、`is_fallback`、`fallback_reason`），`GET /api/v1/health` 的 `degraded` 字段会列出当前哪些服务在降级。演示和写说明书时请以这些标记为准，如实说明。

其余可调项（端口、上传大小、并发任务数、视频尺寸、转场时长、字幕字体等）见 `.env.example` 里的注释。

## 3. 通用功能

### 上传校验（`server/uploads.py`）
页面图片支持 png / jpg / webp / bmp，提问录音支持 wav / mp3 / webm / ogg / m4a。校验内容：扩展名白名单、文件头与扩展名是否一致、大小上限（默认 20 MB）、图片能否完整解码、像素总数上限、最小 64×64。文件名由服务端生成，不使用客户端传来的名字。上传整本书时任何一页不合格就整体拒绝，不会留下半本书。

### 任务队列（`server/task_queue.py`）
旁白和视频生成都是异步任务。状态每次变化都写到 `logs/tasks/<task_id>.json`，服务重启后仍能查到历史任务；重启时没跑完的任务标记为失败（`INTERRUPTED`）。相同目标的任务未结束时重复提交会返回同一个任务。取消：排队中的直接取消，执行中的在当前页处理完后停止。

### 异常与重试（`server/errors.py`、`server/retry.py`）
所有错误都转成统一外壳和稳定的错误码。未预料的异常只返回 `INTERNAL_ERROR`，不向调用方暴露内部细节，详情在服务端日志里按 `run_id` 查。外部服务调用失败时，只对“再试可能成功”的情况重试（超时、连接失败、429、5xx），默认最多 3 次，间隔按 1 秒、2 秒、4 秒递增并加随机抖动；4xx 和返回格式错误不重试。

### 运行记录（`server/run_logger.py`）
见 [logs/README.md](../logs/README.md)。每次生成一个 JSON 文件，记录 run_id、时间、输入、提示词版本及文件哈希、模型及参数、输出文件路径及哈希、耗时、费用、错误、上级 run_id、代码提交号。密钥字段写入前会被遮蔽。

## 4. 旁白生成（步骤 4）

入口：`POST /api/v1/generate/narration`，或命令行 `python scripts/generate_book.py --book <book_id> --steps narration`。

做法是“讲述原书”，不是创作：

1. 输入取自分页数据：本页原文、画面摘要、情节、人物设定表、上一页旁白。
2. 提示词在 `configs/prompts/narration_v1.txt`。文件名就是版本号；要改提示词请另存为 `narration_v2.txt` 并把 `agents/story_agent.py` 里的 `PROMPT_NAME` 指过去，不要直接改旧文件，这样旧结果仍可追溯。
3. 调用方式沿用参考代码的故事模块（OpenAI 兼容的 chat/completions，地址、密钥、模型都来自环境变量，可以接 DeepSeek、Qwen 等，代码不绑定厂商），温度 0.3。
4. 生成后做程序化检查：

| 检查 | 不通过时 |
|---|---|
| 旁白为空 | 重试 |
| 超过长度上限（绝对上限 220 字，且不超过原文长度的 2.5 倍加 20 字） | 重试 |
| 明显短于原文（不到一半） | 重试 |
| 夹带标记、括号说明、音效标签 | 重试 |
| 原文里出现的人物没有被讲到 | 重试 |
| 内容大多找不到原文依据（依据度低于 0.15） | 重试 |
| 依据度偏低（低于 0.30）、原文保留偏少、把规范称呼换成了别名、出现“小朋友你知道吗”这类互动 | 多试一次，仍有问题则采用但标记“需人工复核” |

“依据度”是旁白里相邻两个字的组合有多大比例能在本页原文、画面摘要、情节、人物和物体名称里找到，是一个粗略的防编造指标，不能代替人工复核。

5. 重试时会把上一次的输出和没通过的原因一起发给模型。最多 3 次仍不通过，或大模型调用失败、预算用完，就**退回直接朗读原文**，保证不会把编造的内容讲给孩子。
6. 写回 `narration` 和 `narration_meta`，并把 `safety_check.status` 重置为 `pending_review`。

## 5. 视频生成（步骤 5）

入口：`POST /api/v1/generate/video`，或命令行 `python scripts/generate_book.py --book <book_id> --steps video`。

每页的流程：

1. **提示词**：`configs/prompts/video_v1.txt` 模板，填入本页画面摘要、情节、本页人物的外观设定、上一页和下一页的画面摘要，并固定要求“画风、配色、人物造型不变，不新增人物和文字，镜头缓慢”。
2. **配音**：旁白 → TTS → `audio/page_NNN.wav`。
3. **图生视频**：原绘本页插图作为首帧 → `video/raw/page_NNN.mp4`。协议沿用参考代码的网关（提交、轮询、下载）。首帧默认以 base64 直接放进请求，不需要参考代码里的 OSS 图床。
4. **合成**（MoviePy）：片段等比缩放居中到 1280×720 画布，不裁剪；页时长取“旁白时长 + 0.8 秒”和 3 秒中较大的；片段不够长时先放慢（最多到 1.25 倍时长），再用最后一帧定格补足；叠加字幕（按句切分，按字数分配时间）→ `video/clips/<clip_id>.mp4`。
5. 全部页完成后**拼接**成 `video/book.mp4`，页间 0.5 秒交叉淡入。每页的 `time_range` 取“本页开始到下一页开始”，相邻页首尾相接。
6. **写回**每页的 `video_clip_id`、`time_range`、`video_prompt`、`narration_audio`、`video_meta`，书级的 `video`，并导出 `video/clip_index.json` 给 B 建检索。

带 `page_no` 提交时只做到第 4 步，生成这一页的成片，不动整本视频；这时书级 `video.stale` 会被置为 `true`，表示整本需要重新拼接。

### 缓存与费用控制

- 配音、图生视频片段、单页成片都按输入内容做缓存。输入没变（同一张图、同一段提示词、同一个模型和参数）就直接复用，不再调用收费服务。只改旁白时，图生视频片段不会重做。
- `force: true`（命令行 `--force`）才会忽略缓存重新调用。
- 每次调用都在 `logs/cost_ledger.jsonl` 记一行：时间、run_id、服务、模型、用量（视频秒数、token、字符数）、金额、绘本和页码。汇总看 `GET /api/v1/costs` 或 `python scripts/generate_book.py --costs`。
- 单价和预算在 `configs/pricing.json`。**单价目前都是空的，需要按服务商的价目表填写**；没填时台账只记用量，金额为空，不会编造价格。
- 预算默认是图生视频每天 30 次、大模型和 TTS 各每天 500 次，可改。达到上限后不再调用对应的收费服务，改用降级方案并写明原因。
- 图生视频调用失败（重试后仍失败）也会改用降级片段，原因写在 `video_meta.fallback_reason`。降级片段不占缓存，下次运行会重新尝试真实服务。

### 字幕字体
自动查找顺序：Noto Sans SC / 思源黑体 / 文泉驿（开源许可）→ 系统自带的微软雅黑、黑体等。用了哪种字体会写进 `video_meta.subtitle_font`，请据此在素材来源清单里披露。Linux 服务器上需要先安装一种中文字体（例如 `fonts-noto-cjk`），或用 `PBSC_SUBTITLE_FONT` 指定字体文件；找不到字体时会跳过字幕并在运行记录里注明。

### 速度参考
本机（无独立 GPU 参与，1280×720，24 帧）用降级方案合成 3 页 28 秒的整本视频约 22 秒，全部是本地编码时间。接入真实图生视频后，总时间主要取决于外部服务的排队和生成时间，目前没有实测数据。

## 6. 命令行脚本

| 命令 | 作用 |
|---|---|
| `python -m server` | 启动服务 |
| `python scripts/generate_book.py --book demo_book` | 不启动服务，直接跑旁白和视频 |
| `python scripts/generate_book.py --costs` | 查看费用汇总 |
| `python scripts/make_sample_book.py --video` | 重新生成示例绘本和示例视频 |
| `python scripts/smoke_reference_server.py` | 逐接口测试参考后端，刷新实测结果表 |
| `python scripts/run_reference_server.py` | 启动参考后端（修正了地址前缀和编码问题） |
| `python -m pytest` | 运行全部测试（71 项，约 45 秒） |

## 7. 目录

```
configs/     settings.py（配置入口）、pricing.json（单价与预算）、prompts/（提示词，文件名即版本号）
agents/      llm_client、story_agent（旁白）、tts_client、i2v_client、video_compose、video_agent（视频）、cost（台账）
server/      app（应用）、api（真实接口）、mock_api（假接口）、task_queue、uploads、run_logger、book_store、errors、retry
scripts/     命令行脚本
tests/       测试
data/samples/demo_book/   自制示例绘本（入库）
data/books/               运行时的绘本数据（不入库）
logs/        运行记录、任务状态、费用台账（不入库）；logs/examples/ 是示例绘本上的记录样例（入库）
docs/        文档
```
